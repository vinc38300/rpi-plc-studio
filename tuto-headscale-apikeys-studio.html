Utiliser headscale apikeys avec RPi-PLC Studio

1Deux clés, deux usages

Headscale utilise deux types de clés qu'il ne faut pas confondre — c'est la confusion la plus fréquente en démarrant :

Clé API (apikeys) Clé de pré-auth (preauthkeys)
Rôle Piloter Headscale lui-même (créer des utilisateurs, des clés, lister les machines…) Enregistrer un seul appareil sur le tailnet
Qui l'utilise Headplane, RPi-PLC Studio, tout script d'automatisation tailscale up --authkey=…, exécuté sur l'appareil à enregistrer
Durée de vie 90 jours par défaut, réutilisable pour toutes les opérations Généralement à usage unique, courte expiration
💡
Ce que fait Studio : tu ne donnes à Studio que la clé API (une seule fois). À chaque déploiement, Studio l'utilise pour générer lui-même une clé de pré-auth fraîche et connecter le RPi — tu n'as plus jamais besoin de manipuler de clé de pré-auth à la main.

2Prérequis

  • Headscale installé et en cours d'exécution sur ton YunoHost (systemctl status headscale → active (running))
  • Un certificat Let's Encrypt valide sur le domaine Headscale et sur celui de Dex (pas de certificat auto-signé)
  • Un utilisateur Headscale déjà créé (ex. vinc) via headscale users create vinc
  • RPi-PLC Studio en version 3.5-10 ou supérieure (intègre le bloc "🔒 Tailscale / Headscale")

3Générer la clé API

Sur ton serveur YunoHost, en SSH :

# Méthode recommandée — YunoHost gère le chemin et le contexte pour toi
sudo yunohost app shell headscale <<< "./headscale apikeys create"

La commande affiche la clé une seule fois, quelque chose comme :

Attention : la clé n'est affichée qu'une seule fois, copiez-la !
a1b2c3d4e5.k9x7m2p4q8r1s5t3u6v0w2y4z8A1B3C5D7E9F1G3H5I7J9K1L3M
⚠️
Copie-la immédiatement dans un gestionnaire de mots de passe ou colle-la directement dans Studio (étape suivante). Headscale ne permet pas de la réafficher — si tu la perds, il faudra en créer une nouvelle et révoquer l'ancienne.

Alternative si la commande ci-dessus échoue

Si yunohost app shell ne fonctionne pas dans ton contexte, la commande directe équivalente est :

cd /var/www/headscale
sudo ./headscale -c ./config.yaml apikeys create

Personnaliser la durée de validité

Par défaut la clé expire au bout de 90 jours. Pour une autre durée :

sudo yunohost app shell headscale <<< "./headscale apikeys create --expiration 365d"

4Configurer Studio

Dans RPi-PLC Studio :

  1. Ouvre le dialogue de déploiement de ton projet
  2. Va dans l'onglet Avancé
  3. Déroule le bloc 🔒 Tailscale / Headscale — accès distant au RPi

5Ce qu'il se passe au déploiement

Quand tu cliques sur Déployer avec l'option activée, Studio exécute automatiquement, après le déploiement du programme PLC :

  1. Résolution de ton nom d'utilisateur Headscale en ID numérique via l'API
  2. Génération d'une clé de pré-authentification fraîche (24h, réutilisable)
  3. Connexion SSH au RPi, vérification si Tailscale est déjà installé
  4. Installation du client Tailscale si nécessaire (curl install.sh)
  5. Exécution de tailscale up --login-server=… --authkey=… sur le RPi
  6. Récupération et affichage de l'IP Tailscale obtenue dans le journal de déploiement

Tu verras dans les logs de Studio une ligne du type :

[TS] ✅ RPi joignable en permanence sur : 100.64.12.3 (port 5000)

6Lister / révoquer une clé

Lister les clés existantes

sudo yunohost app shell headscale <<< "./headscale apikeys list"

La colonne Prefix identifie chaque clé (c'est la partie visible même après création, contrairement au reste de la clé).

Révoquer une clé (perdue, compromise, ou remplacée)

sudo yunohost app shell headscale <<< "./headscale apikeys expire --prefix <PREFIX>"
⚠️
Une fois expirée, la clé arrête immédiatement de fonctionner partout où elle est utilisée (Studio, Headplane, scripts…). Génère et remplace-la avant de révoquer l'ancienne si tu ne veux pas d'interruption.

7Vérifier la connexion du RPi

  • Depuis Headplane : onglet Machines — le RPi doit apparaître avec son hostname et une IP 100.x.x.x
  • Depuis le RPi en SSH : 
    tailscale status
tailscale ip -4
  • Accès à la synoptic à distance, où que tu sois : 
    http://<IP_TAILSCALE_DU_RPI>:5000/synoptic

8Sécurité & bonnes pratiques

  • Génère une clé dédiée à Studio, différente de celle utilisée par Headplane — plus facile à révoquer isolément en cas de besoin
  • Si ton projet .plcproj est versionné avec git, ne commite jamais ce fichier une fois la clé API renseignée, ou ajoute-le à .gitignore
  • Préfère une expiration raisonnable (90 jours) plutôt qu'une validité illimitée, et renouvelle-la périodiquement
  • Une clé API donne un contrôle large sur Headscale (création d'utilisateurs, de clés, etc.) — traite-la comme un mot de passe root, pas comme un simple jeton de lecture

9Dépannage

« Error: connecting to headscale: connecting to ./headscale.sock: context deadline exceeded »

Le service Headscale ne tourne pas. Vérifie :

sudo systemctl status headscale
sudo tail -30 /var/log/headscale/headscale.log

Causes fréquentes : certificat auto-signé sur le domaine Dex (voir yunohost domain cert status), ou service jamais redémarré après une modification de config.

Erreur HTTP 401 / « Unauthorized » côté Studio

❌
La clé API est invalide, mal copiée (espace en trop), ou a expiré. Génère-en une nouvelle avec apikeys create et remplace-la dans Studio.

« Utilisateur Headscale introuvable »

Le nom saisi dans Studio ne correspond à aucun utilisateur Headscale. Vérifie la liste :

sudo yunohost app shell headscale <<< "./headscale users list"

Le RPi n'apparaît pas dans Headplane après déploiement

  • Vérifie que le RPi a bien un accès réseau sortant vers l'URL Headscale (pas de pare-feu local bloquant)
  • Consulte les logs de déploiement dans Studio — la ligne [TS] indique la cause précise si l'étape a échoué
  • Sur le RPi : sudo tailscale status pour voir l'état de la connexion côté client
